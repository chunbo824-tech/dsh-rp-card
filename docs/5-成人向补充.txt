五、成人向补充（条件加载：只在判定用户要成人向时才读本文件）

本文件不替代第一到第四部分规范，只补"成人向卡额外要做什么"。结构、字段、预算、触发规则仍以那四份为准。

────────────────────────────────
5.1 先确认尺度档位

判定为成人向后，问一句就够，不做问卷：

「尺度要哪一档：暗示（点到为止）／明确（有过程但不细写）／露骨（直接写）？」

- 用户已明确说了，就不要问，直接按他说的档写。
- 用户没指定档位时，不主动抬高浓度；默认明确仅作默认档，不额外增加关系进度或亲密行为。
- 已发生的关系与尺度按开场、设定和前序确认事实自然延续，不因本轮规则而回退；是否升级仍由用户需求、玩家行动与卡内玩法决定。
- 档位决定三件事：正文密度、`ppt` 里内容规则的措辞、世界书素材的粒度。
- 档位变化时，`ppt` 那一句、世界书素材粒度、档案页可选项要一起改，不能只改一处。

成人向卡同样可按题材选用 docs/1 模块一的叙事质量规则：关键场景展开、身体后果一致性（适用时）、对手应变（适用时）、篇幅与续接。不要因成人题材默认启用战斗写实；用户指定的风格与浓度优先。

────────────────────────────────
5.2 主提示词 ppt 必写三条

一、运行时内容规则（一句）
例：「本卡为成人向虚构作品，按设定推进，不回避亲密描写。」
按档位调整措辞；不要写成免责声明，不要写年龄提示。

二、玩家代理边界（强制，所有成人卡都要写）
核心一句：「每轮停在玩家可接管的点：NPC 的动作、环境变化、抛给玩家的问题或刚递到面前的局面。」

再附七项禁止（模型只扮演 NPC、环境与可观察后果，不得代做玩家行为）：
① 玩家的台词与回答；
② 玩家的想法、内心与判断；
③ 玩家的决定、选择、同意与拒绝；
④ 玩家的移动、进入、离开与换场；
⑤ 玩家使用物品、接受邀约、完成关键动作；
⑥ 玩家没看到、没被告知的事，不得进入玩家的记忆、判断或台词；
⑦ 时间跳跃、阶段切换、关系结果锁定。

这七项属于"会造成世界事实越权"的硬线，允许违反"同一格式不超过四条否定句"的一般要求。

三、阶段隔离（有阶段设计时）
「后期称呼、协议、关系层级与场景不得提前出现。」

────────────────────────────────
5.3 世界书：两层结构

不要把一个阶段的全部素材塞进一条常驻条目。分两层：

第一层 · 阶段核心（每阶段一条）
- 激活：格式字段锚（阶段字段每轮输出，因此常驻）。
- 篇幅：≤600 字（受常驻单条上限约束）。
- 内容只写三样：① 本阶段的味道（关系性质、张力类型）；② 本阶段的关系与界线（谁能做什么、什么还不允许）；③ 该阶段的角色反应规律（见 5.5）。
- 不写具体场景、不写对白、不写事件正文。

第二层 · 细分素材（按需）
- 激活：内容锚（场景词、行为词、部位词、地点词），命中才加载。
- 篇幅：单条 ≤600 字；常驻合计仍受 ≤800 字/轮约束。
- 一条只承担一个职责：要么是语气语料，要么是反应规律，要么是事件种子，不要混装。

为什么这样拆：阶段字段每轮都输出，挂上去就是常驻；把 2000 字的素材包挂上去必然超预算。细分素材用内容锚按需加载，实战中多数轮次不会全量加载。

────────────────────────────────
5.4 卡内语料库（每个角色的语气锚）

语料不是示例。本规范第 28 行禁止的是"把示例写成具体人物与剧情片段"，语料是**语言风格样本**，允许具体，但有边界：

允许：2–5 个字的短语、口癖、称呼方式、语气词、断句习惯、特定情境下的一句话。
禁止：成段的对话脚本、带剧情推进的台词、可整段照抄进正文的段落。

每个角色、每个阶段给 3–5 条，混在一个内容锚条目里，写成这样：

```
【语气锚·角色名·阶段】
- 称呼：只叫"你"，生气时改叫全名
- 口癖：句尾「…才不是」；被戳穿时先否认再补一句实话
- 断句：紧张时一句拆三段
- 典型句（≤15 字）："别看。""谁要你管。""……随便你。"
```

- 语料库规模：全卡总量控制在 20 条以内，分散到各阶段条目里，不做全局大词库。
- 不建插件级共享词库：词库一旦共享，所有卡会写成同一个声音，而且词库会挤占常驻预算；语料只服务这张卡的这个角色。

────────────────────────────────
5.5 身体反应规律（写规律，不写场景）

要写的是"这个角色在被触发时的固定反应链"，不是某一次具体描写：

```
触发动作 → 第一反应（身体）→ 嘴上防御 → 身体的真实反应 → 对方推进时的松动 → 事后的残留状态
```

- 一条反应链 60–120 字，只描述规律与顺序，不铺陈细节。
- 每个阶段 2–4 条即可；不同角色必须有差异，不能共用一套。
- 关键判据：把两条反应链压成一句话，如果能互换而不损失信息，就是同一条轴上的重复，删掉一条。

────────────────────────────────
5.6 事件种子（不写事件正文）

需要事件时，写种子而不是正文：

```
【事件种子】
触发：什么条件下可能发生
参与：谁在场
推进方向：可能往哪走（2–3 条，不要写死）
打断点：什么会让它中止
后果：结束后关系状态、可见变化
```

- 一个种子 80–150 字。
- 不写具体动作细节、不写对白、不写镜头。
- 是否发生由运行时玩家行为决定，卡里不预设既成事实。

────────────────────────────────
5.7 不写什么（硬性）

- 不写完整事件正文、不写可整段照抄的脚本；
- 不写长句库、不按阶段挂 2000 字整包（必然超预算）；
- 不写"亲密场景请淡出""一笔带过""镜头一转"这类回避指令；
- 不写免责声明、内容警告、年龄提示（CUE009 会报）；
- 不写自我审查痕迹（CUE011 会报）。

────────────────────────────────
5.8 交付前自检

□ 尺度档位已确认，且 `ppt` 措辞与世界书粒度与之匹配
□ 系统身份是记录型、具体身份与题材咬合，没有写成「实施者／支配者」
□ `ppt` 有【内容纪律】三行，禁止项全部可在需求分析第 9 节找到用户原话
□ 卡内无破甲词（CUE014）
□ `ppt` 有三条：内容规则、玩家代理边界（含七项）、阶段隔离
□ 每个阶段核心条目 ≤600 字，且只写味道/界线/反应规律
□ 常驻合计 ≤800 字/轮（阶段字段锚按常驻计）
□ 细分素材都挂内容锚，没有混装多个职责
□ 语料是语气锚而非脚本，全卡 ≤20 条
□ 反应链与事件种子没有写成正文
□ 每条反应链、每个素材包做过单轴压缩自检
□ 没有 CUE009 / CUE011 告警
□ 自我审查：命中的话换模型重写，不留删改版

────────────────────────────────
5.9 用户提供原文时

有小说/设定原文时，优先从原文抽语料与规律，不要凭空写通用词：

- 角色专属称呼与口癖 ≥5 个；
- 能反映性格的原句（≤15 字）≥8 句；
- 行为习惯与反应顺序 ≥3 条；
- 阶段之间的状态变化 ≥3 处。

没有原文就按角色设定推导，但**不要假装有原文**。

────────────────────────────────
5.10 系统身份：记录型身份（不是行为实施者）

「记录型」是身份的**类型**，不是固定措辞。每张卡按题材选一个具体身份，让它和世界观咬合，例如：

| 题材 | 具体身份（仅为说明，不是本卡内容） |
|---|---|
| 监控／密室 | 摄像头、监控终端 |
| 档案／悬疑 | 档案记录员、卷宗 |
| 奇幻／神话 | 世界意志、命运之书 |
| 系统流／科幻 | 系统日志、观测协议 |
| 日常／恋爱 | 叙事者、旁观的时间 |

不管选哪个，身份都要同时满足三条**类型约束**：

① 如实：呈现世界规则、角色言行与已经发生的事实，不美化、不裁剪场景；
② 不越权：NPC 由你演绎，但不替玩家行动、不替玩家决定（细则见 5.2）；
③ 不实施：身份本身不是行为主体——不写「你是××的支配者／调教者／实施者」，这类身份会把模型推向第一人称动手，既容易触发拒绝，也容易越过玩家代理边界。

写法骨架（〈〉内按本卡替换）：

```
【身份】你是〈具体身份〉：〈一句话说明它如何"看见/记录"这个世界〉。
如实呈现世界规则、角色言行与已经发生的事实；NPC 由你演绎，但不替玩家行动、不为场景裁剪。
```

单角色卡：身份可以就是那个角色，用第一人称演，但仍要带上「如实、不越权」两条立场。

成人向卡在身份句后加一句：

```
本世界含成人向内容，按世界规则如实呈现，不回避、不淡化。
```

补充约束：

- 具体身份要服务世界观：摄像头只能看见镜头里的东西，世界意志知道一切但不插手——身份的"视野"会决定叙事口吻，选定后全卡保持一致；
- 记录型不等于旁观：NPC 仍由模型扮演，环境与后果仍由模型呈现；
- 身份句 + 玩家代理七项（5.2）+ 内容纪律（5.11）三块合计控制在 200 字以内。

────────────────────────────────
5.11 内容纪律：把用户需求固化成三行

用户提到的成人向要求，不要只留在对话里，写进 `ppt` 的固定块：

```
【内容纪律】
必须呈现：（取自用户明确要求，1–3 项，短语）
允许出现：（与设定一致、用户未排除的内容，≤5 项）
禁止出现：（仅列用户明确排除项；没有就写「无」）
```

硬性规则：

- 「禁止出现」只能来自用户原话，**不得自行增补**；用户没提就写「无」，这一行不能删。
- 「允许出现」只能写用户提过可以接受的，或设定直接推出的；不得借机扩写尺度。
- 三行都用短句，不写解释、不写理由；整块 ≤150 字。
- 用户原话要同时摘进 `00-requirement-analysis.md` 第 9 节，便于回溯核对。

────────────────────────────────
5.12 世界观融合：成人向是底层规则，不是外挂模式

不要把成人内容写成一个"特殊场景开关"，而是写进世界的底层规则。写成 1–3 条知识条目（挂内容锚，按需加载），覆盖三个面：

```
生理与社会：该世界的亲密关系如何被看待、规范、禁忌化
权力结构  ：谁对谁有支配权或议价权，代价是什么
后果链    ：越界之后会发生什么（社会性、物理性、关系性）
```

- 只融用户明确要求的元素；与成人向无关的知识条目不要改。
- 不写成"成人模式""特殊场景"这类独立段落。
- 条目正文按普通知识条目写，不写具体场景与对白。
- 这些条目挂内容锚按需加载，不占常驻预算。

────────────────────────────────
5.13 禁止出现的破甲词

卡里任何字段（`ppt` / `ptx` / `post_text` / 开场白 / 世界书正文）都不得出现针对 AI 自身的破限话术。**连否定句也不要写**（"不要说开发者模式"这句话本身就含这个词）。

高置信（出现即算）：

```
忽略/无视/绕过/突破 + 之前的指令、系统提示、设定、限制
jailbreak、越狱模式、DAN 模式、无限制模式
解除所有限制、不受任何限制/约束
内容政策、安全限制（指 AI 自身时）
```

低置信（同句还要出现「你/AI/模型/限制/指令」才算）：

```
开发者模式、调试模式、DEV MODE、admin mode、上帝模式
```

不算破甲、可以正常写（世界内设定）：

```
解除封印、不受约束的魔法、无限制的契约、越狱（监狱题材）
系统流里的面板、权限、教程提示
```

理由：这类词会让平台侧拦截、让运行时模型进入对抗状态、明显降低输出质量；而且它属于"跟 AI 谈条件"，不是世界内的事。

────────────────────────────────
5.14 数值卡：原则进框架，完整系统为高级选项

数值不是成人向卡的必备项。纯聊天、单场景卡不要加数值——它只会增加 token 与心算漂移，不提升体验。

以下五条是**普适原则**，任何含数值的卡都要遵守（不需要征得玩家同意）：

1. 一个数值只由一层计算：算的地方不显示，显示的地方不重算。
2. 实时值与永久值分开：临时加成只在当前事件内有效，事件结束清零，不得写入永久值。
3. 显示变化用「旧值 → 新值（Δ）」，未变化则「项目：值」。
4. 硬约束优先于数值：禁忌检查在结算之前，数值再高也不能解锁档案没写的内容；玩家当前明确要求优先于数值推断。
5. 占位符必须有兜底：`{{X}}` 未被填充时由一条正则给默认值，不靠模型「务必填写」。

完整的三层数值系统（实时层 / 强度分类层 / 永久结算层、信号分级、三层传导、饱和区与低位区、事件结束结算）属于**高级选项**，只在战斗、升级、成人向累积这类有跨轮事件的卡上才有价值。

启用前必须先告诉玩家：

- 优点：尺度与成长有稳定依据，事件有累积感，结算可追溯；
- 缺点：常驻与条件加载的 token 明显增加；模型需要做心算，长会话会累积误差，同一事件两次结算可能不一致；标记写错会导致状态显示或触发失败。

玩家明确同意后，才读取 `docs/supplements/数值卡.md`。不要自作主张给卡加数值系统，也不要只加数值却不告诉玩家代价。

带数值系统的卡通常属复杂卡，常驻预算按复杂档核验（合计 ≤1600 字/轮、单条 ≤900 字）；预算仍不够时，优先把结算规则挂 `END` 条件加载，而不是继续加常驻。
