# 数值卡（高级选项）

**读取前提**：先向玩家说明优缺点并取得明确同意，再读本文件。没有同意就不要给卡加数值系统。

- 优点：尺度与成长有稳定依据，事件有累积感，结算可追溯。
- 缺点：token 明显增加；模型要做心算，长会话会累积误差，同一事件两次结算可能不一致；标记写错会导致显示或触发失败。

## 一、什么时候值得用

同时满足才建议启用：

1. 有跨轮持续的事件（战斗、训练、经营、探索）；
2. 事件有明确结束点，需要一次结算；
3. 玩家会反复做同类行为，需要累积感。

不满足就别用。纯聊天、单场景、剧情驱动卡一律不用。

## 二、三层结构（按加载时机拆，不要常驻）

| 层 | 什么时候加载 | 职责 | 预算 |
|---|---|---|---|
| 实时层 | 事件进行中（状态行输出 `CONTINUE`） | 累积值、临时加成、阈值判定 | ≤500 字 |
| 分类层 | 事件结束轮（`END`） | 只输出「普通 / 重度」分类 | ≤200 字 |
| 结算层 | 事件结束轮（`END`） | 永久数值结算与写回 | ≤400 字 |

状态行固定输出：`▸ 事件：IDLE` / `▸ 事件：CONTINUE` / `▸ 事件：END`。

- 实时层挂 `CONTINUE`（格式标记锚），只在事件轮加载。
- 分类层与结算层挂精确标记 `▸ 事件：END`，**不要用裸 `END`** 当 key——正文里出现「结束」二字就会误触发，实际等于常驻。
- 走完结算立即回 `IDLE`；`END` 是单轮过渡态，不得连续出现。

## 三、实时层要点

事件开始时建立缓存：初始值、临时加成、累积值、本次事件行为记录。

```text
阈值 = max(基础阈值 − 当前值 ÷ 系数, 下限)
达成值 = 累积 ÷ 阈值 × 100
```

- 每次行动按强度分档累加（如轻 +2 / 中 +5 / 重 +10），**同类同轮只计一次**，跨轮累加。
- 达到阈值：结算一次，累积清零，若为首轮触发则记临时加成并立即重算阈值。
- 临时加成只在本次事件内有效，事件结束全部清除，**不得写入永久值**。
- 事件进行中不结算任何永久数值；全部留到 END。

## 四、分类层要点

只读实时层交来的行为记录，从「冲击强度 / 持续时间与累计量 / 心理或风险深度」三维判断，两项越线即重度；输出只有一个分类词，不碰数值。

「实际表现优先于行为名称」——名字叫得狠不等于重度，写得轻也不等于普通。

## 五、结算层要点

```text
1 判断事件类型 → 2 读事件前数值 → 3 基础变化
→ 4 阶段修正 → 5 专项规则 → 6 特殊联动
→ 7 饱和区/低位区 → 8 clamp → 9 重判阶段 → 10 写入
```

三个必须保留的机制：

- **饱和区**：接近上限时正向变化减半，防止末段跳变。
- **低位区**：接近下限时单次负向变化设上限，防止一次事件清零。
- **固定步长**：基础变化写死整数（如 +3），**不要写 +2～4 这种区间**——区间由模型随机取，不可复现，也无法回归测试。

结算前先查硬约束：禁忌类字段优先于一切数值。

## 六、显示与隐藏

- 状态行显示 `项目：旧值 → 新值（Δ）`，未变化显示 `项目：值`。
- 复合值写成 `总值（永久值 + 临时值）`，只读展示，不在显示层重算。
- 内部标记（如 `∎…∎`、`◇…◇`）用正则清除；占位符 `{{X}}` 用一条正则给兜底值。
- 数值渲染成进度条时，按十位分档写多条区间正则，**具体匹配在前、裸词着色在后**。

## 七、不要这样做

| 反面做法 | 问题 |
|---|---|
| 结算规则直接常驻 | 每条 2000+ 字，直接超预算 |
| key 用裸 `END` / `借衣` 这类短词 | 正文或玩家输入随时误触发，等于常驻 |
| 基础变化写区间 `+2～4` | 不可复现、不可测 |
| 把初始先验表塞进前缀 | 近千字常驻，应移进世界书按身份锚触发 |
| 显示层重新计算 | 两处结果不一致，玩家会看到矛盾数值 |
| 渲染正则 scope 混用 | 用玩家侧规则处理 AI 输出段，部分平台不生效 |
