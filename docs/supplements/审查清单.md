# 审查清单

只在用户要求"帮我审一下这张卡"或交付前想再自查时用。逐项过一遍，不要跳。

## 结构

- [ ] 卡名、`ppt`、`ptx`、开场白齐全；`post_text` 首行是「玩家输入已结束。」，其后放文风约束，没有空字段冒充内容
- [ ] 简介（若写）是 2–3 句钩子；开场白按卡型分流（平台字段 / 第二部分初始指令）
- [ ] 主角归属已判断：玩家自定义主角不搬进 `ppt`；作者给定主角已写入 `ppt`
- [ ] `ppt` 的输出格式首段是【时间地点】且含「时间：」「地点：」；`ptx` 末尾是「以下为玩家输入：」；`post_text` 首行「玩家输入已结束。」，其后只含文风约束
- [ ] 记忆区：短期 ≤5 条、长期 ≤5 条、合计 ≤1000 字符
- [ ] 行动建议 3–4 条，最后一条是自定义
- [ ] 启用平台建议按钮时：原文含 `<suggested_questions>`（前 3 条 `<p>`，第 4 条在块外）；第三部分清理规则排在「编号条目」之前；原 action-card 仍整段包回；记忆卡边界允许空行；CSS 美化的作用域、锚点、字面量按 docs/3 5.8；按下前三行有下沉/内阴影反馈

## 世界书

- [ ] 每条都有正文与触发配置（key / match_type / key_region / value_region / depth / enable）
- [ ] 部署字段默认值：depth=0、probability=100、value_region=1（位掩码 1/2/4 可组合）、key_region=6（2=玩家输入，4=AI 输出，6=两者）、value_type=0；sort 默认 0（0–9999，0 先于 1 注入，越大越靠后）；世界书有条目设为前置词插入时，`ptx` 的 sort 要大于这些条目（排最后）；设为后置词插入时，`post_text` 的 sort 要小于这些条目（排最前）；depth 例外需写明用户明确要求，用途/失效条件记附注（推理 / 长线伏笔 / 特定条件触发但后续难触发且需长期生效可放宽）；玩家自定义人称：短线用三条提示词层规则 depth=20，长线/大世界卡改用输出格式持久化标记（两者兼具或拿不准也走持久化标记）
- [ ] 篇幅预设：与人称同批提问；固定档写进文风约束，自定义档只写世界书（短线 depth=20，长线输出格式标记）；四档为短 800–1000 / 中 1200–1400 / 长 1600–1800 / 超长 ≈3000，只算正文，只作软目标，不做严格验收
- [ ] 常驻合计 ≤800 字/轮，常驻单条 ≤600 字
- [ ] 常驻条目都有锚词来源（`wb-plan.json` 的 anchorSource 能在 ppt / ptx / post 对应位置找到）
- [ ] 路由有兜底分支
- [ ] 状态机的标记在状态行里真的会输出
- [ ] 间接自触发检查：条目正文里的词是否可能被 AI 复述、导致下一轮再次命中（平台不直接扫描正文，这里是 AI 输出侧的间接风险；若本来就要持续加载可保留）
- [ ] 格式锚检查：含空格/冒号/标题符号的触发词，先与 ppt / ptx / post_text / ai_v_prompt 的输出格式比对；一致的是精准格式锚，不一致才改
- [ ] 硬条件检查：城市/野外等互斥规则用 `** 营地 **：城市/野外` 做硬条件是合法设计；不要为了“覆盖更广”改成通用词，除非确认两套规则可共用

## 成人向（若适用）

- [ ] 尺度档位已确认，`ppt` 措辞与世界书粒度与之匹配
- [ ] 系统身份是记录型（具体身份按题材选），不是实施者
- [ ] 【内容纪律】三行齐全，禁止项只来自用户原话
- [ ] `ppt` 写了玩家代理边界（接管点 + 七项禁止）
- [ ] 阶段隔离：后期称呼与关系层级没有提前出现
- [ ] 素材是语气锚／反应规律／事件种子，不是正文与脚本
- [ ] 做过单轴伪丰富压缩自检

## 校验

- [ ] `deliver` 没有 error
- [ ] CUE009（免责话术）、CUE011（自我审查痕迹）、CUE013（缺玩家代理边界）、CUE014（破甲词）、CUE015（缺内容纪律）均无告警
- [ ] 没有把"待验证"当成已验证
